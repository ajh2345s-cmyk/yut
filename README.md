# 도개걸윷모 — 우리 반 1:1 윷놀이

첨부 원본의 Express + Socket.IO 구성을 바탕으로 대전 서버와 화면을 윷놀이 전용으로 재구성했습니다. 원본에는 public 파일 경로와 클라이언트/서버 이벤트 불일치가 있어 함께 수정했습니다. 외부 폰트·이미지 CDN 없이 실행합니다.

## 빠른 실행

Node.js 20 이상이 필요합니다. 프로젝트 폴더에서:

```sh
npm ci
npm start
```

브라우저에서 http://localhost:3000 을 엽니다. 같은 Wi-Fi의 태블릿은 서버 컴퓨터의 내부 IP와 3000번 포트로 접속할 수 있습니다. 인터넷 수업에서는 아래 Cloudtype 배포 주소를 사용하세요.

## 선생님 사용 순서

1. **선생님 입장** → 교실 번호는 비우고 코드 **gmltn** 입력 → 입장.
2. 표시된 **6자리 교실 번호** 또는 **참가 링크**를 학생들에게 알려 주세요. 학생은 선생님 코드가 필요 없습니다.
3. 학생은 교실 번호와 이름(1~12자)을 입력합니다. 동명이인은 번호를 붙입니다.
4. 참가자 관리에서 접속 상태를 확인합니다. 필요하면 참가를 제외할 수 있습니다.
5. **대진표 만들기** → 확인. 이때 접속 중인 참가 대상 학생만 무작위로 배정됩니다.
6. **첫 라운드 시작**. 같은 라운드의 모든 경기가 동시에 시작됩니다.
7. 종료된 학생·부전승 학생은 대진표에서 다른 경기를 눌러 관전합니다.
8. 현재 라운드의 모든 경기가 끝나면 선생님이 **다음 라운드 시작**을 누릅니다.
9. 결승 종료 시 우승자를 표시합니다. **새 대회 준비**는 기존 대회 기록을 지웁니다.

학생은 대진 생성, 라운드 시작, 일시정지, 승자 판정, 초기화를 할 수 없습니다. UI를 우회한 직접 요청도 서버에서 거절합니다. 교사 인증은 코드 기반이므로 이 코드를 아는 사람에게 관리 권한이 부여됩니다. 학생에게 코드를 알려주지 마세요. 코드는 public 파일이나 실시간 공개 상태에 넣지 않았습니다.

## 토너먼트 알고리즘

2~64명 단판 토너먼트입니다. 참가자를 서버의 암호학적 난수로 Fisher–Yates 셔플하고, 인원 이상의 가장 작은 2의 거듭제곱 크기로 대진을 만듭니다. `대진 크기 - 참가 인원` 만큼 첫 라운드에만 부전승을 배정합니다. 빈 자리끼리 경기를 만들지 않습니다. 이후 라운드는 앞 두 경기의 승자가 정해진 자리에 진출합니다. 첫 라운드 이후 추가 추첨이나 추가 부전승이 없습니다.

| 참가 | 대진 크기 | 첫 라운드 실제 경기 | 부전승 | 다음 라운드 | 우승까지 실제 경기 수 |
|---|---:|---:|---:|---|---:|
| 19명 | 32강 | 3경기(6명) | 13명 | 16강 | 18경기 |
| 20명 | 32강 | 4경기(8명) | 12명 | 16강 | 19경기 |
| 16명 | 16강 | 8경기 | 0명 | 8강 | 15경기 |

첫 라운드 부전승 대상은 무작위입니다. 실제 경기는 대진 구역에 분산해 한쪽으로 몰리지 않도록 합니다. 전 대회의 부전승 이력까지 고려하는 순환 배정은 아닙니다. 대진 확정 뒤 들어온 학생은 관전자이며, 다음 새 대회부터 참가할 수 있습니다.

## 수업용 윷놀이 규칙

- 각자 말 **2개**. 두 말 모두 출발·도착 칸을 **지나야** 승리합니다. 도착 칸에 딱 멈춘 말은 다음 이동으로 완주합니다.
- 도 1, 개 2, 걸 3, 윷 4, 모 5칸. **빽도는 없습니다.**
- 서버가 각 윷의 두 면을 50%로 독립 추첨합니다. 도/개/걸/윷/모 확률은 4/16, 6/16, 4/16, 1/16, 1/16입니다. 실제 나무 윷의 물리적 분포를 재현한 것은 아닙니다.
- 윷·모는 결과를 모아 두지 않고 **이동한 뒤 한 번 더 던집니다**.
- 상대 말에 도착하면 잡아서 대기 자리로 돌려보내고 한 번 더 던집니다. 윷·모와 잡기가 동시에 발생해도 추가 던지기는 1번입니다.
- 같은 칸의 내 말은 자동으로 업혀서 함께 이동합니다. 대기 자리에 있는 두 말은 업히지 않습니다. 업힌 말이 잡히면 둘 다 돌아갑니다.
- 오른쪽 위/왼쪽 위 모서리에 멈추면 다음 이동에서 지름길 또는 바깥길을 고릅니다. 모서리를 지나가는 중에는 지름길로 꺾지 않습니다.
- 중앙을 지나갈 때는 진입한 대각선의 반대편으로 직진합니다. 오른쪽 위 대각선에서 중앙에 딱 멈추면 다음 이동에서 출발점 방향 지름길 또는 기존 대각선 방향을 선택합니다. 왼쪽 위에서 중앙에 멈춘 경우에는 출발점 방향으로 갑니다.
- 선공은 매 경기 무작위입니다. 무승부·턴 제한 시간은 없습니다. 수업 시간이 부족하면 선생님이 해당 경기 화면에서 승자를 지정할 수 있습니다.

## 접속 끊김과 관전

- 닉네임 옆에는 접속 표시를 붙이지 않습니다. 학생별 접속 상태는 선생님 참가자 목록에서만 보입니다.
- 학생 연결이 끊기면 해당 경기의 조작이 차단됩니다. 자동 패배 처리는 하지 않습니다.
- 선생님 연결이 끊기면 전체 경기 조작이 차단됩니다. 같은 화면에서 통신 연결만 복구되면 자동으로 이어집니다.
- 학생 신원 토큰은 브라우저 메모리에만 있습니다. 페이지 새로고침·닫기 후에는 자동으로 이전 학생 자리를 차지하지 않습니다. 진행 중 기록은 대진 유지를 위해 서버에 남습니다.
- 다시 들어온 학생은 다른 이름(예: `3번 재입장`)으로 관전 입장합니다. 선생님 **참가자 관리 · 연결 복구**에서 끊긴 경기 자리와 재입장한 학생을 선택해 **이 자리로 연결**합니다. 말 위치와 진행 상태가 이어지며 기존 이름을 사용합니다.
- 선생님이 새로고침했다면 원래 교실 번호와 선생님 코드를 입력해 복구합니다. 기존 선생님 연결이 종료된 뒤 가능합니다.
- 다른 경기를 관전 중이어도 **내 경기로** 버튼으로 돌아갈 수 있습니다. 다음 라운드가 시작되면 본인의 새 경기로 이동합니다.
- 부전승·탈락·관전자 모두 같은 교실 안의 경기들을 실시간으로 봅니다. 별도 채팅은 없습니다.

## Cloudtype 배포

공식 문서: https://docs.cloudtype.io/ko/developers/node 및 https://docs.cloudtype.io/ko/developers/socketio

1. 압축을 풀고 `package.json`, `server.js`, `game.js`, `public/`, `package-lock.json` 등이 저장소 루트에 오도록 GitHub 저장소에 업로드합니다. `node_modules`는 올리지 않습니다.
2. Cloudtype에서 새 서비스 → **Node.js**(또는 Socket.IO) → 해당 GitHub 저장소를 선택합니다.
3. 다음 설정을 적용합니다.

| 항목 | 값 |
|---|---|
| Node 버전 | 20 이상, 가능하면 22 |
| Install Command | `npm ci --omit=dev` |
| Build Command | 비워 둠 (별도 빌드 없음) |
| Start Command | `npm start` |
| Port | `3000` |
| Health Check | `/health` |
| 환경 변수 | `PORT=3000`, `ADMIN_CODE=gmltn`, `NODE_ENV=production` |
| 인스턴스 수 | **1개** |
| 서브 디렉터리 | 파일이 저장소 루트면 비움. 하위 폴더면 그 폴더 이름 입력 |

4. 배포 후 서비스의 HTTPS 주소를 열어 선생님 교실을 만듭니다. 같은 주소/참가 링크를 태블릿에서 엽니다.
5. 우선 두 기기로 학생 2명의 던지기·이동과 선생님 일시정지, 별도 기기의 관전을 확인합니다.

Docker 배포를 사용할 경우 포함한 Dockerfile로 빌드하면 됩니다. HTTP와 Socket.IO를 같은 3000번 포트로 제공하며 WebSocket 실패 시 Socket.IO의 HTTP polling 전송으로 대체됩니다.

**운영 범위:** 이 버전은 한 Node 프로세스의 메모리에 교실과 경기를 저장합니다. 서버 재시작·재배포·서비스 절전 종료 시 대회 기록은 초기화됩니다. 수업 도중 재배포하지 말고 인스턴스는 1개로 운영하세요. 모든 접속이 종료된 교실은 6시간 뒤 정리됩니다. 여러 인스턴스나 영구 저장이 필요하면 공유 저장소/세션 어댑터가 추가로 필요합니다.

실제 Cloudtype 계정 배포는 이 파일에 포함되지 않습니다. 배포 설정과 실행 소스를 제공합니다.

## 검증

```sh
npm ci
npm test
```

Node 내장 테스트로 2~64명 대진, 19/20명 전 라운드 완료, 윷의 16가지 결과, 경로·잡기·업기·도착, 100개 자동 경기, 학생 권한 차단, 관전자 조작 차단, 중복 요청 차단, 일시정지와 연결 복구를 확인합니다.

브라우저 렌더링·실제 태블릿 검증은 제작 환경의 브라우저 다운로드 시간 초과로 완료하지 못했습니다. 수업 전에 다음 항목을 확인하세요.

- 선생님 1명과 학생 2명이 서로 다른 기기로 입장하고 대진 생성·시작하기
- 양쪽 학생의 윷 던지기와 말 선택, 지름길 선택 버튼 누르기
- 관전 기기에서 같은 말 위치와 경기 결과가 보이는지 확인하기
- 선생님 일시정지 시 학생 조작이 차단되는지 확인하기
- 가로·세로 화면에서 버튼이 가려지거나 가로 스크롤이 생기지 않는지 확인하기
- 학생 재접속 및 선생님의 경기 자리 복구 실행하기

## 파일 구성

- `server.js`: 교실, 교사 인증, 실시간 통신, 권한, 대회 진행
- `game.js`: 윷놀이 규칙, 경로와 대진 생성
- `public/`: 태블릿 반응형 화면
- `test/`: 규칙 및 실제 Socket.IO 통신 테스트
- `Dockerfile`, `.env.example`: 배포 참고 설정

환경 변수 `ADMIN_CODE`를 지정하지 않으면 요청한 기본 코드가 적용됩니다. `.env.example`은 참고용이며 자동으로 읽지 않습니다.
