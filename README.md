# 윷놀이 · yut 2.0

선생님이 통제하는 1:1 교실 윷놀이입니다. 각자 말 2개, 2~64명 단판 토너먼트, 자동 부전승, QR 입장, 실시간 관전, 저장된 경기 자동 복구를 제공합니다.

## 실행

Node.js 20 이상에서 프로젝트 폴더를 열고 실행합니다.

```sh
npm ci
npm start
```

http://localhost:3000 에 접속합니다. 학교 태블릿에서는 배포된 같은 HTTPS 주소를 사용하세요.

## 선생님 진행 순서

1. **선생님** 탭을 선택하고 교실 번호를 비운 채 관리자 코드 **gmltn**으로 입장합니다.
2. 상단 **QR** 버튼을 눌러 학생들에게 보여 줍니다. 처음 들어온 학생은 교실 번호를 입력하지 않고 **이름만** 적습니다. 기존 참가자는 같은 브라우저에 저장된 자리로 자동 입장합니다.
3. **관리**에서 학생 수와 접속 상태를 확인하고, 던지기·이동 시간을 정합니다.
4. **대진표 만들기**를 누르면 모든 기기에 **대진 공개 화면**이 먼저 나옵니다. 이때는 경기가 시작되지 않습니다.
5. 선생님이 **경기 시작**을 눌러 현재 라운드의 모든 경기를 동시에 시작합니다.
6. 해당 라운드가 **모두 종료된 뒤에만** **다음 대진 공개**가 가능합니다. 대진을 보여 준 후 선생님이 다시 **경기 시작**을 누릅니다.
7. 선생님은 **방 이동**으로 같은 교실 안의 모든 경기를 볼 수 있습니다. **관리**에서 현재 관전 중인 경기의 관전자 이름, 학생별 연결 상태, 승리 판정 버튼을 확인합니다.
8. **새 대회 준비**는 대회 기록을 초기화하지만 참가자와 기기 복구 정보는 유지합니다. 새 반은 새 교실을 만드는 것이 편합니다.

관리자 코드는 서버에서만 검증합니다. 학생이 직접 관리 요청을 보내도 거절합니다. 코드 자체를 아는 사람에게 교사 권한이 부여되므로 학생에게는 교실 번호/QR만 알려 주세요.

## 화면과 이동

- 첫 화면의 제목은 **윷놀이**뿐이며 이름 예시와 상시 게임 설명을 없앴습니다.
- 모바일 경기 화면은 윷판, 현재 차례, 남은 시간, 결과, 조작을 한 화면에 배치했습니다. 대진표·경기장 목록·관리·기록은 별도 창으로 엽니다. 많은 경기/참가자 목록은 해당 창 안에서 스크롤합니다.
- 말은 주황/파랑 원 안의 **● / ◆**로 구별합니다. **말 1 / 말 2 버튼은 없습니다.**
- 움직일 색깔 말을 누르면 가능한 도착 칸에 **1~5 숫자**가 표시됩니다. 그 칸을 누르면 이동합니다.
- 윷·모가 나오면 먼저 한 번 더 던져 결과를 쌓습니다. **모 → 도**가 나왔다면 같은 말에 **5칸과 1칸 도착지**가 함께 표시되며, 어느 결과부터 사용할지 선택합니다. 다른 말에 나누어 써도 됩니다.
- 같은 도착 칸에 서로 다른 결과가 겹치면 선택 창으로 사용할 결과를 고릅니다.
- 지름길/바깥길도 가능한 도착 칸으로 함께 표시됩니다. 말판 전체에서 서버가 허용한 이동만 가능합니다.
- 게임을 마친 학생에게 진행 중인 다른 경기 목록이 자동으로 열립니다. 방 제목에는 두 참가자의 이름이 표시됩니다. 부전승 학생도 **방 이동**으로 관전합니다.
- 학생에게는 다른 학생의 접속 상태나 관전자 이름을 노출하지 않습니다. 자신의 네트워크가 끊겼다는 안내와 경기 정지 사유는 표시합니다.

## 진행 시간

**관리 → 진행 시간**에서 던지기와 말 이동을 각각 설정합니다.

| 설정 | 기본값 | 입력 범위 |
|---|---:|---|
| 윷 던지기 | 15초 | 0(무제한), 5~180초 |
| 말 이동 | 30초 | 0(무제한), 5~180초 |

시간 설정을 바꾸면 진행 중인 경기의 현재 동작 제한 시간을 새 값으로 갱신합니다. 이동 시간은 결과 하나를 사용할 때마다 새로 시작합니다. 윷·모의 추가 던지기도 각각 새 시간이 주어집니다.

시간 종료는 패배가 아닙니다. 양쪽 기기에 응답을 확인한 뒤 **자동 던지기 / 자동 이동**합니다. 자동 이동은 완주, 잡기, 큰 이동 결과 순서로 선택하며 동률이면 첫 번째 가능한 말을 택합니다. 기록에 자동 진행이 표시됩니다.

학생 연결 끊김, 학생 화면 이탈, 기기 응답 없음, 선생님 연결 끊김, 선생님 일시정지 중에는 시간을 멈춥니다. 복구되면 남은 시간부터 이어집니다. 화면 이탈 이벤트 없이 전원이 갑자기 꺼져도 시간 종료 직전 응답 검사를 통과하지 못하면 자동 진행을 멈춥니다. 짧은 통신 확인 지연은 생길 수 있습니다.

## 재접속과 저장

**이번 버전은 재입장해도 기록을 이어 갑니다.**

- 기기에 `localStorage`로 참가 토큰을 저장합니다. 새로고침, 브라우저 종료 후 재실행, 같은 링크/QR 재접속 시 원래 이름·말·차례·대진으로 돌아갑니다.
- 같은 기기에서 복제 탭을 열면 새 연결을 사용하고 이전 탭을 종료해 중복 조작을 막습니다.
- 서버는 매 던지기·이동·대진 변경 등을 디스크에 저장합니다. `state.json.tmp` 작성 후 원자적으로 교체하고 이전 파일은 `.bak`에 둡니다. 진행 시간은 최대 5초 간격으로 체크포인트를 남깁니다. 비정상 서버 종료 시 마지막 체크포인트의 남은 시간으로 복구될 수 있습니다.
- 서버 프로세스가 재시작되면 모든 접속을 끊긴 상태로 복구합니다. 선생님과 양쪽 학생이 다시 들어온 뒤 이어집니다. 재시작 때문에 승패가 바뀌지 않습니다.
- 시크릿 모드 종료, 사이트 데이터 삭제, 다른 브라우저/기기 사용, 배포 주소 변경 시 기기 토큰을 찾을 수 없습니다. 새 이름으로 관전 입장한 뒤 선생님이 **관리 → 다른 기기로 옮기기**에서 기존 자리와 연결해 주세요. 기존 자리의 이름과 경기 기록을 유지합니다.
- **이름 변경 / 다른 교실** 버튼은 해당 기기의 자동 복구 토큰을 지웁니다. 연결된 교실의 진행 기록을 삭제하지 않습니다. 진행 중 실수로 사용했다면 선생님이 복구할 수 있습니다.
- 동명이인은 번호를 붙입니다. 이름만으로 다른 사람의 자리를 되찾을 수 없게 했습니다.

### 서버 재배포까지 보존하려면

브라우저 복구와 서버 파일 보존은 별개입니다. **영구 저장 볼륨 없이 컨테이너를 교체하면 경기 파일이 사라질 수 있습니다.** Cloudtype에서 제공되는 저장 공간/볼륨 옵션을 확인하고, 실제 마운트 경로에 `DATA_FILE`을 맞춰 주세요. 예를 들어 `/app/data`를 영구 저장 경로로 마운트했다면:

```text
DATA_FILE=/app/data/state.json
```

해당 경로는 서비스 실행 계정에 쓰기 권한이 있어야 합니다. 이 파일과 `.bak`은 참가 토큰을 포함하므로 `public/`에 넣거나 GitHub에 올리지 않습니다. 실제 영구 볼륨 연결은 배포 계정에서 설정해야 하며, 소스의 환경 변수만으로 저장 공간이 생성되지는 않습니다.

## Cloudtype 배포

기본 설정은 [Cloudtype Node.js 공식 안내](https://docs.cloudtype.io/ko/developers/node)를 기준으로 합니다. 이 패키지는 실제 계정 배포를 수행하지 않은 소스입니다.

1. `yut.zip`을 풀고 `package.json`, `server.js`, `public/` 등이 GitHub 저장소 루트에 오도록 올립니다.
2. Cloudtype에서 Node.js 서비스를 만들고 해당 저장소를 선택합니다. Dockerfile 배포도 가능합니다.
3. 아래 설정을 적용합니다.

| 항목 | 값 |
|---|---|
| Node.js | 20 이상 (Dockerfile은 22) |
| Install Command | `npm ci --omit=dev` |
| Build Command | 비워 둠 |
| Start Command | `npm start` |
| Port | `3000` |
| Health Check | `/health` |
| 인스턴스/레플리카 | **1** |
| 환경 변수 | `ADMIN_CODE=gmltn`, `PORT=3000`, `NODE_ENV=production` |
| 경기 저장 | `DATA_FILE`을 실제 쓰기 가능한 영구 저장 경로로 지정 |
| QR 외부 주소 | 필요할 때만 `PUBLIC_URL=https://배포주소` |

4. HTTPS 주소로 선생님 입장 → QR 표시 → 태블릿으로 스캔합니다.
5. 학생 2명으로 먼저 시작한 뒤 한 기기를 새로고침해 이름과 말 위치가 복구되는지 확인합니다.
6. 영구 저장 공간을 연결했다면 서버 재시작 후 같은 교실로 복구되는지도 확인하세요.

현재 구현은 단일 서버용입니다. 여러 인스턴스를 동시에 같은 파일에 연결하지 마세요. 별도의 빌드·브라우저 패키지·외부 QR 서비스는 필요 없습니다. QR 이미지는 서버에서 자체 생성합니다. `.env.example`은 참고 파일이며 로컬에서 자동 로드하지 않습니다.

## 적용 규칙과 대진

- 각자 말 2개, 빽도 없음, 잡기·업기·지름길 포함.
- 도 1 / 개 2 / 걸 3 / 윷 4 / 모 5칸. 각 윷의 양면을 50%로 독립 추첨합니다. 결과 확률은 4/16, 6/16, 4/16, 1/16, 1/16입니다.
- 윷·모는 결과를 쌓고 다시 던집니다. 추가 던지기가 끝난 뒤 결과를 원하는 순서로 사용합니다.
- 잡기는 업힌 상대 말도 모두 대기로 돌려보내며 추가 던지기 기회 1회를 줍니다. 이미 쌓인 결과를 모두 사용한 뒤 추가로 던집니다. 한 번의 이동으로 두 말을 잡아도 1회입니다.
- 같은 칸의 내 말은 자동으로 업혀 함께 움직입니다. 대기 말은 별개로 출발합니다.
- 모서리에 정확히 멈춘 뒤 다음 이동에서 지름길을 선택할 수 있습니다. 중앙을 통과할 때는 진입 대각선 방향으로 직진합니다. 오른쪽 위에서 중앙에 정확히 멈추면 다음 이동에서 출발점 방향 지름길도 고를 수 있습니다.
- 출발·도착 칸을 지나야 완주입니다. 그 칸에 딱 멈추면 다음 이동이 필요합니다. 두 말 모두 완주하면 승리합니다.
- 매 경기 선공은 무작위입니다.
- 참가자는 서버에서 무작위로 섞고, 가장 가까운 상위 2의 거듭제곱 대진을 만듭니다. 부전승은 첫 라운드에만 배치하고 실제 경기는 구역별로 분산합니다.

| 참가 인원 | 첫 대진 | 첫 라운드 경기 | 부전승 | 총 실제 경기 |
|---|---|---:|---:|---:|
| 19명 | 32강 | 3경기 | 13명 | 18경기 |
| 20명 | 32강 | 4경기 | 12명 | 19경기 |

대진 확정 이후 입장한 신규 학생은 관전자입니다. 기존 학생의 저장 토큰으로 들어온 경우에는 기존 참가 자리를 복구합니다.

규칙 검토 참고: [경기전통놀이한마당 대회규정](https://ggyunnori.com/), [한국민족문화대백과사전](https://encykorea.aks.ac.kr/). 지역별 윷놀이 세부 규칙은 다르므로 이 앱의 실제 판정은 위 명시한 수업용 규칙과 `game.js`를 따릅니다.

## 검증

```sh
npm ci
npm test
```

자동 테스트 13개: 대진(2~64명), 19/20명 결승까지, 경로, 결과 누적 순서, 잡기·업기, 100개 자동 경기, 권한, 관전자 비공개 범위, QR 생성, 시간 제한, 기기 응답 확인, 저장·서버 재시작·연결 교체를 검증합니다.

브라우저에서 QR 입장, 대진 공개 후 시작, 색깔 말/도착 칸 터치, 새로고침 자동 복구, 시간 설정·일시정지, 경기 종료 후 방 이동, 관리자 관전자 이름 확인을 점검했습니다. 320×568, 390×844, 844×390, 768×1024 화면의 게임 조작 영역과 가로 넘침을 검사했습니다. 실제 학교 기기의 카메라·브라우저 버전·네트워크 상태는 배포 후 확인이 필요합니다.
